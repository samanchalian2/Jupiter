# اتصال یک نرم‌افزار دیگر

این مسیر برای توسعه‌دهنده و مسئول مجاز اتصال است؛ کاربر عادی برای گزارش مشکل به SDK یا کلید احتیاج ندارد. ابتدا Application و environment مشخص و دسترسی‌های مستقل را از مسیر مدیریت پشتیبانی‌شده آماده کنید. قرارداد عمومی OpenAPI و راهنمای integration/reference clients در مخزن observability مرجع فنی هستند؛ endpoint یا مجوز را حدس نزنید.

برای مرورگر از Browser SDK و برای Node از Node SDK و در صورت نیاز adapter React/NestJS استفاده کنید. نمونه‌های مستقل Browser، Python و C# برای اثبات قرارداد موجودند. هسته نباید به جدول یا منطق تیکت/سازمان ژوپیتر وابسته شود؛ host باید هویت را از نشست معتبر خودش تأمین کند.

اعتبارنامهٔ مرورگر کوتاه‌عمر و محدود به هویت/برنامه/محیط است؛ کلید مدیریتی یا سرویس را در bundle مرورگر نگذارید. ادعای هویت یا tenant در payload نباید منبع مجوز شود. نام عملیات، route template، دسته، شدت و metadata مجاز را بفرستید، نه URL حساس یا payload خام.

ابتدا در محیط آزمون، ارسال batch، پاسخ جزئی، تکرار همان شناسه، قطع ارتباط، برگشت اتصال، logout و revoke را آزمایش کنید. شناسهٔ یک رویداد هنگام retry ثابت می‌ماند. بررسی کنید رد گزارش یا قطعی Hub مسیر اصلی نرم‌افزار را متوقف نکند. گزارش‌های تشخیصی SDK با رویداد تجاری و quota مشتری فرق دارند؛ دادهٔ گزارش‌شده را اندازه‌گیری مستقل سرور فرض نکنید.

پس از آزمون، مجوزها، محدودیت حجم/نرخ، retention و مانیتور مستقل خارج از process را بازبینی کنید. اتصال موفق یک نمونهٔ ساده، تأیید خودکار کارایی، امنیت و آمادگی انتشار production نیست.
